# 在 dsh-recall-plugin 找简化

寻找有证据支撑的简化：先证明可达性与权衡，再提删除。这是指导，不是脚本。本 skill 与两条长期规则同向：单文件有效行数 800 上限与「超限只降不升」的棘轮、以及「优先复用现有模块」——简化是它们的主要供给来源。

## 确立范围与受保护设计

评判前读 `AGENTS.md`（架构与文件地图）、`docs/compat-audit.md` 的 I1–I30 台账（每条都是踩过的坑）、`docs/plans/pending/` 的活跃计划。以下设计承重或救过火，**不提议删除**，除非有 issue 级证据推翻其价值：

- 影子仓库独立 git + 项目零污染（含 home 三档回退与旧容器迁移 M2、store 心跳 M3）；
- tag 即快照主键、索引可从 tag 名反推重建（`rebuildOrphans`）；
- 双轨回退：文件 reset + 官方 `sessions.fork` + 原会话归档（含 `stopActivity` 的归档护栏）；
- 安全快照 `snap-pre-rollback-*` 与 H1 救援编排、intent journal 崩溃恢复（A2）、失败善后熔断；
- preview/execute 与快照/gc 共用串行队列；
- index.json/lineage.json 的 tmp+rename 原子写与损坏 fail-loud 隔离；
- 工作区根命中排除表的早退（issue #18：78.4MB 不减 → 归零的那场火）；
- G1 队列清理（`staleQueueItemIds`）——它修的是「凭空多一条排队消息」的真实回归。

大范围审计按域拆给子代理（host 存储层 / host 端点层 / client / 测试与脚本 / 散文），各自带证据回来。

## 搜寻可移除的义务

用这六个问题找候选：

1. 这个功能有从入口到生效的完整路径吗？（端点注册了但 client 从不调用、配置字段读了但不影响行为）
2. 这个状态区分影响任何消费者的行为吗？（错误码、index.json 字段、lineage 记录写了但无人按它分支）
3. 能用更小的显式行为替代整个子系统吗？
4. 消费者能直接读权威值，而不是维护一份要同步的拷贝吗？
5. 这个「策略」其实只是被误当作可插拔的唯一组合吗？
6. 谁在承担这个机制的完整维护成本——测试、文档、台账条目、心智负担？

## 证明可达性与权衡

- `rg` 全量搜：源码、`scripts/`、`.github/`、`cordis.patch.yml`、`package.json`、测试、文档——逐匹配阅读，不数命中数下结论。`lib/` 是构建产物，只用它确认产物与源码一致，不作为可达性证据。
- 每个候选记录：所有者、删除什么、残留什么、最强的保留理由。
- 结论分三类：**不可达删除**（无生产/消费路径）、**行为收窄**（有路径但可简化，须说明哪个可观察行为变了）、**受保护义务**（放弃并写明理由）。

## 保留所有权与失败语义

- git 对象与 tag 的归属：谁创建、谁可达、gc/prune 时谁负责不丢——快照 blob 的可达性是 issue #18 的战场，删「多余」的 index 条目、tag 或清理逻辑前先重读该台账。
- 原子写与隔离语义：tmp+rename、`.corrupt-<ts>` 隔离是数据安全的最后防线，不是可精简的仪式。
- 异步机制的每个 promise、取消路径与清理器要有明确归属；合并机制只在它们表达同一事实时才允许，不得丢失串行队列的顺序保证、救援回滚或首次终局仲裁。

## 基础设施净减少

依赖现状：devDeps 是 esbuild/vitest/@deepseek-ai/schemastery，peerDeps 是 CI 不可得的私有 `@deepseek-ai/*`。用现成依赖替换手写实现，只在确能净简化时提出：识别被删除的实现与测试、演练最可能击败替换的边界行为（编码、锁冲突、win32 句柄延迟释放），且不为保留重复定义而加闸门。新增运行时依赖默认拒绝——插件的依赖会进用户宿主。

## 记录、整合与验证

- 值得做的提案落 `docs/plans/pending/`，骨架：问题 / 方案 / 备选 / 验收标准 / 风险。小的顺手清理（单文件内、无行为变化）直接做，不配提案。
- 新提案先查重：是否已有活跃计划或台账条目覆盖同一对象。
- 验证按改动面跑（见 [pre-push-checks](../pre-push-checks/SKILL.md) 的矩阵）；改了 `src/` 必跑 `npm run build` 保持产物新鲜。
- 报告实际调研范围、候选清单、拒绝项及理由、实际跑过的命令——不把「可以删」说成「已验证可删」。
