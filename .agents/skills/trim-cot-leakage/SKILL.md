# 清理思维链泄漏

思维链泄漏指视角是作者会话而不是仓库的散文：它引用只有那个会话能看到的产物，叙述变更而不是状态，或与一个已经离开的审查者争论。当段落携带事实从句时，修复绝不只是删除——把每个事实改写成在 HEAD 上独立成立的表述，再删掉周围的转录；不携带事实的（审计代码、控制流叙述）直接删除。**必要背景**：[prose-standard](../prose-standard/SKILL.md) 拥有本 skill 应用的完整命题规则。这是指导，不是脚本。

## 唯一检验

对每个可疑段落问：**一个 HEAD 上的读者，拿不到任何会话记录、PR 讨论或未提交草稿，能否解析每一个引用、验证每一条断言？** 不能，就把幸存事实从仓库的视角重述，其余删掉。能，它就不是泄漏，无论听起来多像历史——但可解析只过本 skill 的门槛：在 README、docs、JSDoc 这类当前状态表面上，可解析的变更故事仍然算变更叙述，第 3 类会把它送去该去的地方。

## 分类

1. **死设计会话引用**——`(decision 7)`、`(audit C2)`、`design §4.7`、`plan §1.4`、阶段标签（`T4`、`W3`、`P-I`）、「设计台账」、「(B 裁决)」。如果决策有已提交的拥有者，按名字与路径引用它；否则删掉引用，把其事实从句重述为独立成立的表述。
2. **栈与 PR 视角**——「本栈的后一个 PR」「本 PR 新增」「上一个提交」。陈述已交付的机制或扩展点；延后工作移进 `TODO` 标记或 issue 引用。
3. **变更叙述与版本戳**——「以前」「不再」「旧版 X」以及索引性时间戳（「v1」「本版」「今天」「现在」与过去状态对比）。陈述当前行为；已修复的回归写成现在时反事实（「没有 X，就会 Y」），绝不写成仓库历史（「以前会 Y」）。
4. **审阅编排**——「评审中被拒：」「审查者确认」「本笔记第 5 稿」、轮次归属。把幸存的决策与理由保留为平实事实；删掉谁在什么时候说的。
5. **对审查者说理的辩护**——「这个断言是安全的——它只是……」「这里正确是因为……」。为自身正确性辩护的注释面向审查者，而不是维护者。陈述让代码安全的不变量；代码本身就展示它时，删掉注释。
6. **复述与推导转录**——控制流叙述（「先 X，然后 Y」）、测试走查、显而易见分支的证明。删除；只保留非显而易见的契约或不变量。
7. **含糊与规划残留**——「暂时应该够用」「大概够了」、没有标记的延后。升级为 `TODO`/`FIXME` 或改写成实际边界；删掉含糊。
8. **作者语言滑出**——中文文档里夹着未翻译的英文工作片段，或英文文档里夹着「端」「设计稿」「---- 私有 ----」这类分隔符。翻译或删除。

## 什么不是泄漏

不做校准的引用清理会双向失败：删掉持久引用，留下死引用。以下保留规则按字面执行，[样例](references/examples.md) 对每条做了校准：

- **issue 引用**——`#1470`、`TODO(name):`、「issue #N 拥有后续」在 HEAD 上可解析；在任何表面（包括 README）都保留。不要把它们挪进计划记录。
- **计划与实施记录里的已合并 PR、issue 引用**——属于该体裁认可的变更故事证据。
- **抑制理由**——`oxlint-disable … -- 原因`、覆盖率忽略理由、空 catch 的解释是必需散文；修正错误的理由，绝不删除。
- **现在时反事实回归钉**——「没有 X，就会 Y」「朴素的 X 会……」。
- **实测边界**——「(实测：512 层 ≈ 0.15s)」用于校准常量；出处词「实测」是承重词。
- **运行时新旧状态**——「旧连接排空后新连接才接受」是运行时生命周期，不是变更历史。
- **计划记录变更故事小节里的历史阶段名**——「首版交付了 X」在那类小节里对当前状态安全；索引性时间戳（「本版」）在任何地方都禁止。
- **按设计在仓库外解析的外部引用**——标准条款（RFC 9110 §10.1.5）、Figma 帧名；`§` 禁令针对未提交的内部草稿，不针对外部标准或拥有自己 § 编号的已提交文档。
- **项目口吻与体裁形式**——「我们」作为项目口吻；备选方案小节。

## 工作流

1. 范围与排除遵循 [prose-standard](../prose-standard/SKILL.md)：必须有明确 scope；永不触及 `docs/reference/`（官方镜像）、`lib/`（构建产物）、`docs/plans/completed/` 与 `docs/upgrade-assessments/`（冻结历史）。`docs/screenshots/` 与构建派生物是派生物，不是散文目标：只在授权的行为变更要求新证据时重新生成。
2. 先只读审计：跑[检索探针](references/recall-batteries.md)（带 `--hidden` 以便搜到 `.agents/`），每个探针先用一个已知正例和一个近似反例校准再信任其输出，然后对每个命中做语义判断。探针是探针，不是定义——每一轮审查都找到过探针漏掉的案例，所以还要不带模式地读范围内最密集的散文（模块 JSDoc、README、计划记录）。
3. 按表面先修拥有者：派生文案或产物 → 追每个消费者，修源 JSDoc 或构建脚本，再重新生成所有派生物；双语散文 → 最小化更新另一侧，保持结构对齐；用户可见字符串 → 走 [prose-standard](../prose-standard/SKILL.md)，只随拥有它的行为证据改动，否则保持不变并报告延后。
4. 删除任何东西之前，枚举段落的命题（prose-standard），并对照[过度修正陷阱](references/examples.md#过度修正陷阱)：把义务翻成背书的精简、把假设提升为已交付功能、删掉真事实、丢掉出处。
5. 验证：重跑探针，预期只剩受认可的保留项、本 skill 自身目录与拥有者记录的引证；确认每个剩余引用在 HEAD 上可解析；对触及的表面跑相应检查（文档改动跑 `npm run typecheck`、`npm test` 与 `git diff --check`）。
